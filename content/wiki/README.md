# 维基工作区说明

本目录是 LLM Wiki 的维基层，包含所有由 LLM 生成和维护的页面。

## 目录结构

```
wiki/
├── entities/         # 实体页面 (人物、组织、技术、项目等)
├── concepts/         # 概念页面 (理论、方法论、抽象概念等)
├── summaries/        # 源文件摘要 (原始源文件的提炼)
├── comparisons/      # 比较分析 (不同实体/概念的对比)
├── synthesis/        # 综合页面 (跨领域的整合内容)
├── index.md          # 内容索引 (所有页面的目录)
├── log.md            # 操作日志 (按时间顺序的操作记录)
└── SCHEMA.md         # 维基结构规范 (页面格式和工作流程)
```

## 核心原则

### 1. LLM 维护
- 所有页面由 LLM 生成和维护
- 保持内部一致性
- 自动更新交叉引用
- 定期健康检查

### 2. 页面类型

#### 实体页面 (entities/)
记录具体的实体，如:
- 人物: Andrej Karpathy, 研究人员等
- 组织: OpenAI, Anthropic 等
- 技术: Transformer, RAG 等
- 项目: 具体的项目或产品

**文件命名**: `实体名称` (小写和连字符)

#### 概念页面 (concepts/)
记录抽象概念和理论，如:
- 方法论: LLM Wiki Pattern
- 理论: 知识管理理论
- 框架: 三层架构

**文件命名**: `概念名称` (小写和连字符)

#### 摘要页面 (summaries/)
原始源文件的提炼，如:
- 文章摘要
- 论文摘要
- 文档摘要

**文件命名**: `来源-日期` (如 `karpathy-llm-wiki-20260410`)

#### 比较分析 (comparisons/)
对比不同实体或概念，如:
- LLM Wiki vs Traditional RAG
- 不同工具的比较

**文件命名**: `主题-对比` (如 `llm-wiki-vs-traditional-rag`)

#### 综合页面 (synthesis/)
跨领域的整合，如:
- 领域全景图
- 综合分析报告
- 知识地图

**文件命名**: `综合主题` (如 `ai-knowledge-management-landscape`)

### 3. 核心文件

#### index.md
内容总目录，帮助快速定位所有页面。
- 按类别组织
- 包含每个页面的简短描述
- 链接到所有维基页面
- 每次摄入时自动更新

#### log.md
操作日志，记录所有维基活动。
- 摄入记录: `## [YYYY-MM-DD] ingest | Title`
- 查询记录: `## [YYYY-MM-DD] query | Question`
- 维护记录: `## [YYYY-MM-DD] lint | Description`
- 追踪维基演进历史

#### SCHEMA.md
维基结构规范，定义:
- 页面格式模板
- 工作流程
- 命名和链接约定
- 元数据规范
- 质量保证标准

## 工作流程

### 摄入流程
1. 阅读源文件 (来自 `input/raw/`)
2. 创建摘要页面 (在 `summaries/`)
3. 更新或创建相关实体/概念页面
4. 更新 `index.md`
5. 在 `log.md` 中记录

### 查询流程
1. 查找 `index.md` 定位相关页面
2. 读取相关维基页面
3. 综合信息形成答案
4. 有价值的答案可创建新页面
5. 在 `log.md` 中记录

### 维护流程
1. 定期检查维基健康状态
2. 查找矛盾、过时内容、孤立页面
3. 更新和优化内容
4. 在 `log.md` 中记录

## 质量标准

- **准确性**: 信息准确，引用恰当
- **一致性**: 术语和风格一致
- **完整性**: 关键信息不遗漏
- **可追溯**: 有明确的源文件引用
- **可维护**: 结构清晰，易于更新

## 元数据规范

每个页面应包含 YAML 前言:

```yaml
---
tags: [tag1, tag2]
created: YYYY-MM-DD
updated: YYYY-MM-DD (可选)
author: 作者 (可选)
sources: [source1, source2] (可选)
---
```

## 最佳实践

1. **保持简洁**: 页面不要太长，拆分为多个页面
2. **频繁链接**: 大量使用内部链接 `[[页面]]`
3. **定期维护**: 每周或每月进行健康检查
4. **版本控制**: 使用 Git 追踪所有更改
5. **持续演进**: 根据使用经验优化结构和流程

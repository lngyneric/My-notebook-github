# 多智能体协作（Multi-Agent Collaboration）

> 本页内容编译自 `raw/05_代码与项目/agentic-design-patterns/agentic-design-patterns/13-Chapter-07-Multi-Agent-Collaboration.md`

---

## TL;DR
多智能体协作是解决单智能体能力瓶颈的Agent设计模式：它将复杂跨领域任务按任务分解原则拆分为多个子问题，分配给不同专长的独立智能体，通过标准化通信与协作机制协同完成目标，能获得比单个智能体更优的结果，具备更好的模块化、可扩展性与鲁棒性。

---

## 模式概述
单智能体架构在处理边界清晰、定义明确的任务时表现良好，但面对复杂跨领域任务时能力会受到明显限制。多智能体协作模式通过将系统组织为一组相互协作的专长型智能体来解决该问题，核心思路是**任务分解**：将高层目标拆解为独立子问题，每个子问题分配给拥有对应工具、数据权限或推理能力的智能体处理。

例如一个复杂研究问题可分工为：研究智能体负责信息检索、数据分析智能体负责统计处理、综合智能体负责生成最终报告。

该模式的效果不仅来自分工，更依赖智能体间的通信机制，需要标准化通信协议和共享本体，支撑智能体交换数据、委派子任务、协调行动，保证最终输出连贯一致。

这种分布式架构的优势包括：
- 更强的模块化、可扩展性
- 更好的鲁棒性：单个智能体故障不一定导致整个系统瘫痪
- 协同效应：多智能体系统的整体表现通常超过任何单个智能体的能力上限

## 常见协作形式
多智能体协作可采用多种形式：
| 协作形式 | 说明 |
|---------|------|
| **顺序交接（Sequential Handoffs）** | 一个智能体完成任务后将输出传递给下一个智能体，形成管道式工作流，和规划模式类似，但明确涉及多个不同智能体 |
| **并行处理（Parallel Processing）** | 多个智能体同时处理问题的不同部分，最终合并结果 |
| **辩论与共识（Debate and Consensus）** | 来自不同视角、拥有不同信息来源的智能体通过讨论评估方案，最终形成共识或得到更可靠的决策 |
| **层级结构（Hierarchical Structures）** | 管理型智能体根据执行型智能体的工具/能力动态分配任务，最终汇总结果；每个智能体只负责一组相关工具，避免单个智能体承担所有工具调用责任 |
| **专家团队（Expert Teams）** | 不同领域具备专业知识的智能体（如研究员、撰稿人、编辑）协作，共同完成复杂输出 |
| **评审者模式（Critic-Reviewer）** | 一组智能体生成初始输出（计划、草稿、答案等），另一组智能体从合规性、正确性、质量、目标对齐等维度评估输出，原始生成智能体或最终智能体再根据反馈改进输出；该模式在代码生成、研究写作、逻辑检查、伦理合规校验场景效果尤其好，可提升鲁棒性与输出质量，降低幻觉和错误概率 |

一个完整的多智能体系统通常包含三个核心部分：
1. 明确每个智能体的角色和职责
2. 建立用于信息交换的通信通道
3. 制定引导协作的任务流程或交互协议

## 智能体交互与通信模型
理解智能体的交互和通信方式是设计高效多智能体系统的基础，从简单到复杂存在多种不同的互联模型，各有优劣，会直接影响系统的效率、鲁棒性和灵活性：

### 1. 单智能体（Single Agent）
最基础的模型，单个智能体独立运行，不需要和其他智能体交互，实现和管理简单，但能力受限于单个智能体的范围和资源，适合可被分解为独立子问题、每个子问题都可由单个自给自足智能体解决的场景。

### 2. 网络化（Network）
多个智能体以去中心化、点对点的方式直接交互，可共享信息、资源、分担任务，弹性较好：单个智能体故障不一定影响整个系统；但在大规模非结构化网络中，难以控制通信开销，也很难保证决策一致性。

### 3. 监督者（Supervisor）
专门的监督者智能体作为中心枢纽，负责监督协调下级智能体，承担任务分配、冲突解决的职责，职责清晰，简化管理控制；但存在单点故障问题，当下级数量过多或任务过于复杂时，监督者容易成为系统瓶颈。

### 4. 将监督者视为工具（Supervisor as a Tool）
监督者模型的微调扩展，监督者不再直接指挥控制，而是为其他智能体提供资源、指导或分析支持，不干预智能体的每一步行动，既可以发挥监督者的能力，又避免僵化的自上而下控制。

### 5. 层级（Hierarchical）
在监督者模型基础上扩展为多层组织结构：高层监督者监督低层级监督者，最底层是执行智能体；适合可拆分为多个子问题的复杂任务，每一层管理特定子问题，为应对复杂性和实现可扩展性提供清晰结构，支持在边界内分工决策。

### 6. 自定义（Custom）
最高灵活性的设计，可针对特定问题精确定制交互和通信结构，可以是融合已有模型特点的混合方案，也可以是全新设计；通常用于需要优化特定指标、处理高度动态环境或需要集成领域特定知识的场景，设计实现要求对多智能体原理有深入理解，需要仔细规划通信协议、协调机制和可能的涌现行为。

选择通信模型是多智能体系统的关键设计决策，最优选择取决于任务复杂度、智能体数量、所需自治程度、鲁棒性要求、可接受的通信开销等多个因素。

## 典型应用场景
多智能体协作是通用模式，适用于多个领域：
1. **复杂研究与分析**：参考人类研究团队分工，不同智能体分别负责检索文献、总结要点、归纳趋势、合成报告
2. **软件开发**：分工为需求分析、代码生成、测试、文档编写等不同智能体，协同开发验证组件
3. **创意内容生成**：营销策划场景可分工为市场调研、文案撰写、素材设计、社媒排期等智能体协同完成
4. **财务分析**：不同智能体分别负责获取股票数据、分析新闻情绪、技术分析、生成投资建议
5. **客户支持**：一线支持智能体处理常见咨询，复杂问题按领域升级给对应专业智能体（如技术专家、计费专家）
6. **供应链优化**：智能体代表供应链不同节点（供应商、制造商、分销商），协同优化库存、物流、排期，应对需求变化和突发状况
7. **网络分析与故障修复**：多智能体协同完成故障定位和问题排查，可和现有机器学习模型、运维工具集成，结合生成式AI的能力提升自主运维效果

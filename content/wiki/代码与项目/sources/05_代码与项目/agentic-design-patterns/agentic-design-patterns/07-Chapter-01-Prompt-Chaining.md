# Chapter 1: Prompt Chaining | 第一章：提示链

## TL;DR
提示链（也叫管道模式）是大语言模型处理复杂任务的核心智能体设计模式，核心思想是**分而治之**：将复杂任务拆解为顺序执行的多步子任务，前一步的输出作为后一步的输入，每一步聚焦解决一个特定问题。这种模式天然具备模块化、可调试、高可靠的特点，能有效缓解单一复杂提示带来的指令遗漏、上下文漂移、错误放大、幻觉等问题，是构建多步骤 LLM 应用的基础模式。

---

## 提示链模式概述

### 核心思想
提示链（Prompt Chaining，也称为管道模式）是利用大语言模型处理复杂任务的一种强大范式。它不期望 LLM 用单一步骤解决复杂问题，而是采用分而治之策略：
> 将原始难题拆解为一系列更小、更易管理的子问题，每个子问题通过专门设计的提示独立解决，前一步的输出传递给下一步作为输入，逐步推进得到最终结果。

### 核心优势
1. **模块化与可解释性**：顺序处理天然带来模块化特性，每个步骤独立，更容易理解、调试和优化，整体流程更稳健、可解释性更强。
2. **渐进式逼近结果**：前序操作的上下文和结果引导后续处理，LLM 可以在之前工作的基础上深化理解，逐步接近目标结果。
3. **可集成外部能力**：每一步都可以插入外部工具、API 或数据库调用，突破 LLM 内部训练数据的局限，让 LLM 成为更大智能系统的组件，而非孤立模型。

### 单一提示的局限性
对于多维度复杂任务，单一复杂提示效率低，容易出现多种问题：
| 问题 | 描述 |
|------|------|
| 指令遗漏 | 模型忽略提示的部分要求 |
| 上下文漂移 | 模型丢失初始上下文信息 |
| 错误放大 | 早期错误会在后续流程中不断放大 |
| 窗口超限 | 长需求超出模型上下文窗口，导致信息不足 |
| 幻觉加剧 | 过高认知负荷会大幅提升生成错误信息的概率 |

示例：如果要求 LLM 单次调用同时完成「分析市场研究报告、总结结论、提取带数据支撑的趋势、草拟发送给团队的邮件」，模型很可能总结做得不错，但在提取数据或草拟邮件环节出错，最终整体失败。

### 提示链的改进方案
提示链将上述任务拆解为顺序聚焦的工作流，大幅提升可靠性：
1. **第一步（总结）**：仅要求模型总结报告核心发现，模型聚焦单一任务，提升第一步准确率
2. **第二步（识别趋势）**：基于第一步的总结，提取三大新兴趋势和对应支撑数据，直接基于验证过的前序输出处理
3. **第三步（撰写邮件）**：基于第二步的输出，草拟简洁的邮件给市场团队

这种拆解带来更精细的控制，每一步更简单明确，降低 LLM 认知负荷，最终输出更准确可靠。还可以为每个步骤分配不同角色进一步提升质量，比如第一步让模型扮演市场分析师，第二步扮演行业分析师，第三步扮演专业文档撰写人。

### 结构化输出的关键作用
提示链的可靠性高度依赖步骤间传递数据的完整性，如果前一步输出模糊、格式错误，会直接导致后续步骤失败。因此**要求每一步输出结构化格式（如 JSON、XML）是构建稳健提示链的关键实践**。

例如趋势识别步骤可以要求输出如下 JSON 格式，保证数据可被机器精确解析，无歧义插入下一步：
```json
{
  "trends": [
    {
      "trend_name": "AI-Powered Personalization",
      "supporting_data": "73% of consumers prefer to do business with brands that use personal information to make their shopping experiences more relevant."
    },
    {
      "trend_name": "Sustainable and Ethical Brands",
      "supporting_data": "Sales of products with ESG-related claims grew 28% over the last five years, compared to 20% for products without."
    }
  ]
}
```
结构化格式可以大幅减少自然语言解析带来的错误，是构建稳健多步骤 LLM 系统的核心环节。

## 实际应用场景

提示链是通用基础模式，适用于绝大多数需要多步处理的智能体场景，常见应用包括：

### 1. 信息处理工作流
针对需要对原始信息进行多轮转换的任务，典型流程：
1. 从 URL/文档提取文本内容
2. 清洗后总结文本
3. 从总结/原文提取特定实体（姓名、日期、地点等）
4. 用提取的实体搜索内部知识库
5. 结合总结、实体、搜索结果生成最终报告

应用领域：自动化内容分析、AI 研究助手、复杂报告生成。

### 2. 复杂问答
针对需要多步推理或信息检索的复杂问题，典型示例（问题：`1929 年股市崩盘的主要原因是什么？政府的应对政策是什么？`）：
1. 识别用户问题中的核心子问题（崩盘原因、政府应对）
2. 单独检索 1929 年崩盘原因的信息
3. 单独检索政府应对政策的信息
4. 整合两步信息得到连贯回答

复杂工作流通常会结合并行+提示链：独立的信息采集步骤并行处理提升效率，依赖顺序的整合、润色步骤用提示链处理。

### 3. 数据提取与转换
将非结构化文本转为结构化格式通常需要迭代顺序处理，典型流程（发票提取示例）：
1. 尝试从发票提取指定字段（姓名、地址、金额）
2. 验证是否所有字段都提取完成、格式符合要求
3. 如果有缺失/格式错误，生成新提示要求模型专门补全/修正，可带上一步失败的上下文
4. 重复验证，直到结果符合要求
5. 输出经过验证的结构化数据

还可以在流程中插入外部工具弥补 LLM 能力缺陷：例如提取文本后将文字表述的数字转为数值，再把计算任务交给外部计算器，最后整合精确结果，得到单次 LLM 调用难以实现的准确输出。

适用场景：表单、发票、邮件等非结构化来源的数据处理，OCR 后处理等。

### 4. 内容生成工作流
复杂内容创作天然可以拆解为多阶段顺序流程，典型流程：
1. 基于用户兴趣生成 5 个候选主题
2. 用户选择/自动选择最优主题
3. 基于选定主题生成详细大纲
4. 按大纲要点逐段撰写草稿，每一段带上文保证上下文连贯
5. 对完整初稿进行连贯性、语气、语法润色，得到最终内容

适用场景：创意故事撰写、技术文档编写、各类结构化文本生成。

### 5. 有状态的对话智能体
提示链为维持多轮对话连续性提供了基础机制：每轮对话都构建为新提示，系统性融入之前交互的信息和提取的实体，维护对话状态。典型流程：
1. 处理用户第一轮发言，识别意图和关键实体
2. 更新对话状态，保存意图和实体
3. 基于当前状态生成响应，或识别下一个需要收集的信息
4. 后续每一轮用户输入都重复这个过程，不断积累对话状态（历史信息）

这是对话智能体的基础原理，让智能体在长多轮对话中保持上下文连贯，正确处理依赖历史信息的用户输入。

### 6. 代码生成与优化
功能性代码生成通常是多阶段过程，适合用提示链拆解：
1. 理解用户需求，生成伪代码或实现大纲
2. 基于大纲编写初始代码
3. 识别代码中潜在错误或可优化点（可结合静态分析工具或额外调用 LLM）
4. 基于发现的问题重写/优化代码
5. 添加文档和测试用例

提示链允许在两次 LLM 调用之间插入确定性逻辑，实现中间处理、输出验证、条件分支等控制流，把一个复杂的不可靠请求转化为结构化的可管理操作序列，在 AI 辅助开发场景非常实用。

### 7. 多模态多步推理
分析包含多种模态的复杂数据时，需要拆解为多步提示任务。例如解析包含图片、内嵌文本、高亮标注、说明表格的复杂图像，流程可以拆分为：
1. 从用户图像请求中提取并理解文本内容
2. 将提取的文本和对应标签做关联
3. 结合表格

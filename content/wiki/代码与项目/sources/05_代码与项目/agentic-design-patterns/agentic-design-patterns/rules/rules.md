# 《Agentic Design Patterns》 中文翻译规则和指南

## 摘要
本文档是《Agentic Design Patterns: A Hands-On Guide to Building Intelligent Systems》中英文对照翻译项目的官方翻译规则与规范，明确了翻译的核心原则、格式要求、术语统一标准、标点空格规范、质量控制流程与提交规范，保障翻译项目产出统一、准确、符合中文阅读习惯的智能体设计模式学习资源。

## 项目概述
本项目目标是将《Agentic Design Patterns: A Hands-On Guide to Building Intelligent Systems》翻译为高质量中英文对照版本，为中文读者提供优质的智能体设计模式学习资源。

## 核心原则
### 1. 准确性和忠实性
- 翻译内容必须与原文含义完全一致
- 不得随意增删、修改原文内容
- 保留原文的逻辑结构与论述顺序

### 2. 可读性和本土化
遵循翻译界通用的**信雅达原则**：
- **信（Faithfulness）**：准确传达原文含义，不得曲解、漏译、随意增译，保持原文逻辑结构，技术概念必须精确对应
- **达（Expressiveness）**：符合中文表达习惯，拆分长句、避免生硬直译，优先保障读者理解而非逐字对应
- **雅（Elegance）**：在保持技术文档专业性严谨性的基础上追求表达流畅，避免过度文学化

具体实践要求：
- 拆分英文长句为中文短句，单个中文段落不超过3-4行，技术段落适当拆分，用空行分隔内容层次
- 允许为提升流畅度做必要意译与句式调整，保持段落级别对应即可，句子可灵活处理
- 全书语体统一，删除不必要冗余词汇，避免口语化表达，仅在必要场景使用加粗强调

## 格式要求
### 文档结构
- 保留与原文一致的文档结构，二级标题之间用`---`横线分隔提升阅读体验
- 所有标题采用**双语对照格式**，中文翻译使用`<mark>`标签包裹高亮

### 双语布局规范
- 短内容（如致谢）：采用完整英文 + 完整中文分区格式
- 长内容（正文章节）：采用段落对照格式，英文段落后紧跟对应中文翻译段落

### 高亮规范
- 默认所有中文翻译内容使用HTML `<mark>`标签实现高亮，GitHub全兼容
- `<mark>`内不嵌套Markdown语法，加粗使用`<strong>`、斜体使用`<em>`
- 列表标记必须放在`<mark>`标签外，如：`- <mark>条目内容</mark>`

### 标点与细节规范
- 中文术语引用英文缩写使用中文全角括号，如：`大语言模型（LLM）`
- 中文引号统一使用「」，禁止使用英文直引号
- 参考文献采用英文原文在前、中文翻译在后的对照格式

## 技术术语统一规范
### 核心术语翻译标准
| 英文 | 规范中文翻译 | 说明 | 首次出现格式 |
|---------|---------|------|------------|
| Agent | 智能体 | 核心概念，禁用「代理/代理人」 | 智能体（Agent） |
| Agentic | 具智能体特性 / 智能体式 | 形容词，视语境选用 | - |
| AI Agent | AI 智能体 | 完整表述 | - |
| Multi-Agent | 多智能体 | 复合词 | - |
| Canvas | 技术底座 | 隐喻性术语 | 技术底座（canvas） |

### 其他术语规则
- 所有技术术语首次出现采用「中文（English）」格式标注，后续统一使用中文
- 专有名词（Google、GitHub等）保持原文，技术缩写保留大写，用全角括号标注在中文译名后
- **强制禁用「代理」作为`Agent`的翻译，所有场景必须替换为「智能体」**
- 中文翻译中引用代码组件（类名、函数名、变量名等）必须用`<code>`标签包裹，框架、语言、概念术语不需要添加

## 翻译指南补充
### 空格规则
中文与英文、中文与数字之间必须增加一个空格，示例：`AI 系统`、`21 个章节`。

### 标点规范
- 中文语境统一使用中文标点
- 引号强制使用直角引号「」，不使用英文引号
- 中文注释用全角括号（），英文内容/数学公式用半角括号()
- 简单并列（3项以内）用顿号、复杂并列/分句用逗号

### 文化适配
适应中文读者阅读习惯，在保证准确性的前提下做适配，避免过度本土化改变原文含义。

## 质量控制与提交规范
### 快速自检清单
翻译完成后可通过命令行工具自检：
1. 格式检查：确认高亮内加粗/斜体使用正确HTML标签、列表标记位置正确、图注格式统一
2. 标点检查：替换所有中文段内的英文直引号，确认术语括号为全角
3. 术语检查：清除所有残留的「代理」翻译，确认核心术语统一
4. 质量检查：排查笔误、过长单句与过度文学化表达

### PR审阅检查项
提交Pull Request前需确认：翻译符合信雅达标准、格式符合规范、术语统一、标点正确、无冗余编辑标注混入正文。

### 文件命名规范
遵循阿拉伯数字编号加连字符分隔英文标题的格式，如`07-Chapter-01-Prompt-Chaining.md`对应第一章：提示链。

### Git提交信息规范
提交信息使用清晰英文，格式为：
- 新增翻译：`Add: [章节名称] translation`
- 更新格式：`Update: [章节名称] formatting`
- 修复问题：`Fix: [具体问题] in [章节名称]`

# Wiki 架构设计文档

## 核心理念

采用 Andrej Karpathy 提出的 LLM Wiki 模式，通过 LLM 作为知识维护者，自动构建和维护持久化知识库，实现知识的复合增长。

## 三层架构

### 1. 输入层 (Input Layer / Raw Sources)
- **位置**: `input/` 目录
- **内容**: 所有原始源文件，包括文章、论文、文档、图像等
- **特性**:
  - 不可变（只读）
  - 真实数据源
  - 由用户手动添加或通过 Web Clipper 收集
  - 按时间或主题组织
- **子目录建议**:
  - `input/raw/`: 原始文章和文档
  - `input/assets/`: 图像和多媒体资源
  - `input/sources/`: 其他源文件

### 2. 维基层 (Wiki Layer)
- **位置**: `wiki/` 目录
- **内容**: LLM 生成和维护的 Markdown 页面
- **特性**:
  - 完全由 LLM 生成和更新
  - 包含摘要、实体页面、概念页面、比较分析等
  - 保持内部一致性
  - 自动交叉引用
- **页面类型**:
  - 实体页面 (Entities): 具体人物、组织、技术等
  - 概念页面 (Concepts): 抽象概念、理论、方法论
  - 源摘要 (Source Summaries): 原始源文件的提炼
  - 比较分析 (Comparisons): 不同实体/概念的对比
  - 综合页面 (Synthesis): 跨领域的整合内容
  - 索引页面 (Index): 内容目录
  - 日志页面 (Log): 按时间顺序的操作记录

### 3. 输出层 (Output Layer)
- **位置**: `output/` 目录
- **内容**: 从维基层生成的衍生内容
- **特性**:
  - 基于维基内容的二次创作
  - 包括演示文稿、图表、报告等
  - 支持不同格式导出
- **格式示例**:
  - `output/slides/`: Marp 格式的幻灯片
  - `output/reports/`: 综合报告
  - `output/visualizations/`: 图表和可视化
  - `output/presentations/`: 演示文稿

## 核心文件

### index.md (内容索引)
- **作用**: 目录式索引，帮助快速定位内容
- **内容**:
  - 所有页面的链接列表
  - 每个页面的一句话摘要
  - 可选的元数据（日期、源文件数等）
  - 按类别组织（实体、概念、源文件等）
- **更新**: 每次摄入新源文件时自动更新

### log.md (操作日志)
- **作用**: 按时间顺序记录所有操作
- **内容**:
  - 摄入记录 (ingest): `## [2026-04-10] ingest | Article Title`
  - 查询记录 (query): `## [2026-04-10] query | Question`
  - 维护记录 (lint): `## [2026-04-10] lint | Health check`
- **用途**:
  - 追踪维基演进历史
  - 帮助 LLM 了解最近的操作
  - 可用简单命令查询：`grep "^## \[" log.md | tail -5`

## 工作流程

### 摄入流程 (Ingestion Workflow)
1. 用户将新源文件放入 `input/raw/`
2. 通知 LLM 处理新文件
3. LLM 阅读源文件并讨论关键要点
4. 创建或更新相关维基页面（可能涉及 10-15 个页面）
5. 更新 `index.md`
6. 在 `log.md` 中追加摄入记录

### 查询流程 (Query Workflow)
1. 用户提出问题
2. LLM 查找 `index.md` 找到相关页面
3. 读取维基页面并综合答案
4. 答案可以是：
   - Markdown 页
   - 比较表格
   - 幻灯片 (Marp)
   - 图表 (matplotlib)
   - Canvas 画布
5. 有价值的回答可以存回维基作为新页面

### 维护流程 (Maintenance/Lint Workflow)
1. 定期检查维基健康状态
2. 查找：
   - 页面间的矛盾
   - 被新源文件取代的过时声明
   - 没有入站链接的孤立页面
   - 提到但缺少独立页面的重要概念
   - 缺失的交叉引用
   - 可通过网络搜索填补的数据缺口
3. 记录维护操作到 `log.md`

## 特殊工具和插件

### Obsidian 插件
- **Dataview**: 查询页面前言，生成动态表格和列表
- **Marp**: 生成幻灯片演示
- **Excalidraw**: 创建图表和可视化
- **Obsidian Git**: 版本控制
- **Local REST API**: 程序化访问

### 可选工具
- **qmd**: 本地 Markdown 搜索引擎，支持混合搜索
- **Obsidian Web Clipper**: 浏览器扩展，快速将网页转为 Markdown

## 工作方式

- **LLM 角色**: 知识维护者，负责所有维护工作
- **用户角色**: 资源策展人，探索指导者，提出好问题的人
- **工具**: Obsidian 作为 IDE，LLM 作为程序员

## 优势

- **零维护成本**: LLM 不会感到厌倦，不会忘记更新
- **知识复合增长**: 每个新源文件和每次查询都让维基变得更丰富
- **版本控制**: 整个维基是 Git 仓库，支持历史记录和协作
- **灵活性**: 可以根据具体领域和偏好定制

## 实施计划

1. **第 1 阶段**: 设置目录结构，将现有文件夹映射到输入层
2. **第 2 阶段**: 创建 `index.md` 和 `log.md`
3. **第 3 阶段**: 建立摄入流程和查询流程
4. **第 4 阶段**: 开始逐步构建维基层
5. **第 5 阶段**: 优化输出层和工具集成
